## 1. 셸의 두 얼굴

셸은 역사적으로 사용자가 시스템을 쓰는 **주된 인터페이스**였다. 많은 시스템 콜을 **직접이지만 안전하게** 쓸 수 있게 해 준다.

| 얼굴 | 내용 |
|---|---|
| **대화형 명령 프롬프트** | 입력을 받아 바로 실행. 타이핑을 줄이는 기능: 명령 별칭(alias), 최근 명령 불러와 고치기(↑, history) |
| **프로그래밍 환경** | 변수, 조건문, 반복문, 프로시저(함수), 예외 처리. 하지만 핵심 기능은 여전히 **다른 프로그램 실행**이고, 셸 "프로그램"은 대부분 **외부 프로그램들의 조합**이다 |

---

## 2. 단어와 문장

### 단어 (word)

- 셸은 입력을 **단어(문자열)**로 쪼갠다. **셸에서는 모든 것이 문자열**이다.
- 단어는 공백으로 구분된다.
- **첫 단어**가 무엇을 할지 정한다.
- 공백을 단어 안에 넣으려면 따옴표로 감싼다: 작은따옴표 `'`, 큰따옴표 `"`, 백슬래시 `\`.

### 문장 (statement)

- 이전 명령 다음에서 시작해서 **줄바꿈, `;`, `&`**에서 끝난다.
- 파싱한 뒤 셸이 판단하는 것:

| 종류 | 예 |
|---|---|
| 변수 대입 (명령과 함께일 수도) | `DIR_NAME="temp_dir"`, `MYVAR=x ./prog` |
| **내장 명령** | `cd`, `echo`, `export` |
| 제어문 | `if`, `while`, `for` |
| **외부 프로그램** (하나 또는 여럿) | `ls -l`, `cat a \| wc -l` |

## 3. 내장 명령 vs 외부 명령 — `child_cd.c`

### 외부 명령

내장 명령이 아니면 전부 외부 명령이다. 셸은 **`fork()` 후 `exec()`**한다. 첫 단어가 실행할 바이너리, 나머지 단어가 그 바이너리의 인자(`argv`)가 된다.

### 내장 명령

외부 프로그램을 실행하지 않고 **셸 내부 코드**로 처리한다. 이유:

1. **효율**: `fork` + `exec` 비용을 아낌 (`echo`)
2. **셸 자신의 내부 상태를 바꿔야 함** → `fork` 뒤에는 불가능 (`cd`, `export`)

```
$ type cd; type echo; type ls
cd is a shell builtin
echo is a shell builtin
ls is /usr/bin/ls
```

### 왜 `cd`는 내장이어야 하나

```c
// child_cd.c: 자식이 chdir해도 부모는 그대로
if (fork() == 0) {
    chdir("/tmp");
    printf("child  cwd = %s\n", getcwd(buf, sizeof(buf)));
    return 0;
}
wait(NULL);
printf("parent cwd = %s\n", getcwd(buf, sizeof(buf)));
```

```
$ ./child_cd
child  cwd = /tmp
parent cwd = /w
```

```
Shell (cwd: /home/user)
   │ fork()
   ▼
Shell ──exec()──→ cd        (cwd: /home/user/test)
                   ✗ 부모 셸의 cwd에는 반영되지 않음
```

cwd는 **프로세스마다** 있는 상태다 (4강). 외부 `cd` 프로그램은 자기 cwd만 바꾸고 끝나므로, 셸은 `cd`를 직접 `chdir()`로 처리해야 한다.

## 4. 셸 프로그램 예제 — `make_report.sh`

슬라이드 6의 스크립트. 변수, 조건문, 내장 명령(`cd`), 외부 명령(`mkdir`, `touch`, `ls`)이 섞여 있다.

```bash
DIR_NAME="temp_dir"
FILE_NAME="report.txt"

if [ ! -d "$DIR_NAME" ]; then             # -d: 디렉터리가 있나
    mkdir "$DIR_NAME"
    echo "'$DIR_NAME' 디렉토리를 생성했습니다."
else
    echo "'$DIR_NAME' 디렉토리는 이미 존재합니다."
fi

cd "$DIR_NAME" || {                       # cd가 실패하면(종료 코드 ≠ 0) 블록 실행
    echo "디렉토리 이동에 실패했습니다."
    exit 1
}

if [ ! -f "$FILE_NAME" ]; then            # -f: 일반 파일이 있나
    touch "$FILE_NAME"
    ...
```

```
$ ./make_report.sh                       $ ./make_report.sh   (두 번째)
'temp_dir' 디렉토리를 생성했습니다.        'temp_dir' 디렉토리는 이미 존재합니다.
'report.txt' 파일을 생성했습니다.          'report.txt' 파일은 이미 존재합니다.
현재 디렉토리 내용:                        현재 디렉토리 내용:
report.txt                               report.txt
```

- `[`는 사실 `test` 명령이다. `[ ! -d "$DIR_NAME" ]` 안쪽 공백이 꼭 필요하다.
- `A || B`: A가 실패(0이 아닌 종료 코드)하면 B 실행. 셸에서는 **0이 성공**이다.
- 스크립트 안의 `cd`는 **스크립트를 실행한 셸(자식 bash)**의 cwd만 바꾼다. 실행이 끝나도 내 터미널 위치는 그대로다.

## 5. 변수와 특수 변수 — `special_vars.sh`

### 변수

- 셸 변수는 **문자열**이다. 선언할 필요 없고 **전역**이다.
- `VAR=value`: VAR가 없으면 만들고 값을 넣는다.
- **`=` 앞뒤에 공백이 있으면 안 된다.** `VAR = value`는 "`VAR`라는 명령을 인자 `=`, `value`로 실행"이 된다.

### 특수 변수

| 변수 | 의미 |
|---|---|
| `$0` | 현재 실행 파일(스크립트) 이름 |
| `$1` ~ `$9` | 셸(또는 함수)의 첫 9개 인자 |
| `$#` | 유효한 인자 개수 |
| `$*`, `$@` | 모든 인자 |
| `$?` | **직전 명령의 종료 코드** (4강 `WEXITSTATUS`) |
| `$!` | 직전에 **백그라운드**로 실행한 명령의 PID |
| `$PS1` | 대화형 프롬프트 모양 |
| `$IFS` | 치환 결과를 단어로 나눌 때 쓰는 구분자 |

```
$ ./special_vars.sh hello world
$0 = ./special_vars.sh
$1 = hello, $2 = world
$# = 2
$@ = hello world
$? after false = 1
$? after true  = 0
$! = 17 (방금 백그라운드로 실행한 sleep의 PID)
오늘 날짜: 2026-10-27, 이 폴더의 .sh 파일 수: 6
```

## 6. IFS와 따옴표 — `writeargs.sh`, `quote_ifs.sh`

**IFS**(Input Field Separator): 변수 치환 같은 **확장 결과**를 새 단어로 나눌지 정한다. 확장 결과에 IFS 문자가 있으면 거기서 단어가 쪼개진다. 기본값은 **줄바꿈, 탭, 공백**.

```bash
#!/bin/bash
# writeargs.sh
for arg in $*; do
    echo $arg
done
```

```
$ VAR="arg1 arg2"
$ ./writeargs.sh $VAR          # $VAR가 "arg1 arg2"로 바뀐 뒤 공백에서 쪼개짐 → 인자 2개
arg1
arg2
```

### 따옴표에 따라 인자 수가 달라진다

```bash
count() { echo "인자 $#개"; }
VAR="arg1 arg2"
count "$VAR"       # 큰따옴표: 치환은 하지만 쪼개지 않음
count $VAR         # 따옴표 없음: 치환 후 IFS로 쪼갬
count '$VAR'       # 작은따옴표: 치환조차 안 함 (글자 그대로 $VAR)

PATHS="/bin:/usr/bin:/usr/local/bin"
IFS=:
count $PATHS       # 이제 ':'에서 쪼개짐
```

```
인자 1개
인자 2개
인자 1개
인자 3개
```

| 표기 | 변수 치환 | IFS로 쪼개기 |
|---|:---:|:---:|
| `$VAR` | O | O |
| `"$VAR"` | O | **X** |
| `'$VAR'` | **X** | X |

> 파일 이름에 공백이 있을 수 있으면 항상 `"$VAR"`로 감싼다. `make_report.sh`가 `"$DIR_NAME"`처럼 쓴 이유다.

## 7. 변수·명령 치환 — `interp.sh`

변수는 **단어 안에 끼워 넣어진다**(interpolation). 변수 내용이 새 단어를 만들 수도 있다.

| 형태 | 뜻 |
|---|---|
| `$VAR` | 단순 변수 VAR를 끼워 넣음 |
| `${VAR}` | 이름의 경계를 명확히 하거나, 추가 동작을 할 때 |
| `$(command)` | **명령 치환**: 괄호 안 명령을 실행하고 그 **출력**을 그 자리에 넣음 (POSIX 문법) |

```bash
for arg in $*; do
    echo "wrong: file_$argnew.txt"      # "argnew"라는 변수를 찾음 → 없으니 빈 문자열
    echo "right: file_${arg}new.txt"    # arg 뒤에 new를 붙임
done
```

```
$ ./interp.sh arg1 arg2
wrong: file_.txt
right: file_arg1new.txt
wrong: file_.txt
right: file_arg2new.txt
```

명령 치환 예: `echo "오늘 날짜: $(date +%Y-%m-%d)"` → 셸이 `date`를 `fork`/`exec`하고 그 출력을 **파이프로 받아** 문자열에 넣는다.

## 8. 셸 변수 vs 환경 변수 — `env_demo.c`

- POSIX의 모든 프로세스에는 **환경**(key=value 쌍의 집합)이 있다.
- 프로세스는 기본적으로 **부모의 환경을 복사**해서 물려받는다 (`fork` + `exec`).
- 셸 변수는 **`export`하기 전까지 셸 안에서만** 보인다.
- `export VAR [VAR2 ...]`: 이름을 준 변수를 자식 프로세스의 환경에 복사.
- `env` 명령은 자기 환경을 출력하고 끝난다. 셸은 내부에서 `setenv()`/`putenv()`로 환경을 고친다. C에서는 `getenv()`로 읽는다.

```c
// env_demo.c
char *v = getenv("MYVAR");
printf("MYVAR = %s\n", v ? v : "(없음)");
```

```
$ MYVAR=shell_only
$ ./env_demo                 # 셸 변수일 뿐 → 자식에게 안 보임
MYVAR = (없음)
$ export MYVAR
$ ./env_demo                 # 환경으로 복사됨
MYVAR = shell_only
$ MYVAR=one_shot ./env_demo  # 이 명령 하나에만 환경 변수로 전달
MYVAR = one_shot
```

> `export`도 셸 자신의 상태를 바꾸므로 **내장 명령**이어야 한다. `PATH`, `HOME`, `PWD`, `SHELL` 같은 값이 환경 변수의 대표 예다.

## 9. 글로빙 (파일 이름 패턴)

셸은 **글로빙**(파일 이름 패턴 매칭)을 한다. 패턴이 파일 이름과 맞으면 그 **파일 이름 목록으로 확장**된 뒤 명령에 전달된다. 프로그램은 `*`를 보지 못하고 이미 펼쳐진 이름들을 받는다.

| 패턴 | 뜻 |
|---|---|
| `*` | 0개 이상의 아무 문자 |
| `?` | 아무 문자 **정확히 1개** |
| `[...]` | 괄호 안 문자 중 하나. `[a-z]`처럼 범위 가능 |

파일: `stdio.c stdio.h stdio.cpp main.c variant-a.pdf variant-b.pdf variant-e.pdf`

```
$ echo *.c
main.c stdio.c
$ echo *.?                     # 확장자가 한 글자
main.c stdio.c stdio.h         # stdio.cpp는 제외
$ echo *.[ch]                  # .c 또는 .h
main.c stdio.c stdio.h
$ echo variant-[a-d].pdf
variant-a.pdf variant-b.pdf    # variant-e.pdf는 제외
$ echo *.zip
*.zip                          # 맞는 파일이 없으면 패턴 그대로 전달 (bash 기본)
```

글로브는 경로 어디에나 올 수 있다: `lectures/*/*.pdf`.

## 10. 리디렉션과 파이프 — `redirection.sh`

셸은 자기 자신과 자기가 실행하는 프로세스의 fd를 조작할 수 있다.

| 문법 | 시스템 콜 | 뜻 |
|---|---|---|
| `\|` | `pipe()` | 파이프 생성 |
| `<`, `<<`, `>`, `>>` | `open()` + `dup2()` | 파일을 fd에 연결 |
| `N>&M` | `dup2(M, N)` | fd 복사 (새 파일 안 엶) |
| `N>&-`, `<&-` | `close(N)` | fd 닫기 |

| 문법 | 결과 |
|---|---|
| `< file` | 파일을 **stdin(0)**에 연결 |
| `> file` | 파일을 **stdout(1)**에 연결 (자르고 씀, `O_TRUNC`) |
| `>> file` | stdout에 연결, **끝에 덧붙임** (`O_APPEND`) |
| `2> file` | **stderr(2)**만 파일로 |
| `N> file`, `N< file` | 일반형: 파일을 fd N에 `dup2()` |

```
$ ./redirection.sh
2                                                         # wc -l < out.txt  (first, second)
err.txt: ls: cannot access 'no_such_file': No such file or directory
to stderr                                                 # echo ... 1>&2
both.txt: ls: cannot access 'no_such_file': No such file or directory
ls: cannot access 'no_such_file': No such file or directory   # 2>&1 > only.txt 는 화면으로
only.txt: '' (비어 있음)
```

### `2>&1`의 순서가 중요한 이유

리디렉션은 **왼쪽부터** 차례로 `dup2`를 실행한다.

| 명령 | ① | ② | stderr는 어디로? |
|---|---|---|---|
| `ls x > both.txt 2>&1` | fd1 → both.txt | `dup2(1, 2)`: fd2 → (지금 fd1이 가리키는) both.txt | **파일** |
| `ls x 2>&1 > only.txt` | `dup2(1, 2)`: fd2 → (지금 fd1이 가리키는) 터미널 | fd1 → only.txt | **터미널** |

- 에러 메시지를 stderr로: `echo Could not open file 1>&2`
- 에러를 stdout으로 합치기: `./hello_world 2>&1`

### 리디렉션 사용 예 (슬라이드 27)

```bash
wc -w < /usr/share/dict/words              # 파일을 wc의 stdin으로
cut -d' ' -f5 > totals.txt                 # cut의 출력을 파일로
stats -bmean variant-a.txt > means.txt     # 첫 결과는 새로 쓰고
stats -bmean variant-b.txt >> means.txt    # 두 번째는 덧붙임
```

### 파이프라인 `cmd1 | cmd2`

각 명령은 stdout에 쓰고 stdin에서 읽는다. 셸이 하는 일:

1. `pipe()`로 파이프 생성
2. `fork()` 두 번 (cmd1용, cmd2용)
3. `dup2()`: `pipefd[1]` → cmd1의 fd 1, `pipefd[0]` → cmd2의 fd 0
4. 각 자식에서 `exec()`
5. cmd2가 끝날 때까지 `wait`

C로 직접 구현한 코드는 [7강 `pipeline.c`](../07_파이프와_리디렉션/03_리디렉션/pipeline.c)에 있다.

### 셸이 그대로 드러내는 시스템 콜

| 셸 기능 | 시스템 콜 |
|---|---|
| 외부 명령 실행 | `fork()` / `exec()` / `wait()` |
| `>`, `<`, `>>` | `open()` + `dup2()` |
| `N>&M`, `N>&-` | `dup2()`, `close()` |
| `\|` | `pipe()` + `dup2()` |
| `cd`, `export` | `chdir()`, `setenv()` (셸 프로세스 자신에서) |

## 11. O/X 복습 문제

| # | 문제 | 정답 |
|---|---|---|
| 1 | 셸에서 변수 값은 모두 문자열이다 | **O** |
| 2 | `cd`는 `/usr/bin/cd` 같은 외부 프로그램으로 구현할 수 있다 | **X** — 자식의 `chdir`은 셸에 반영되지 않음. 내장이어야 함 |
| 3 | 외부 명령을 실행할 때 셸은 `fork` 후 `exec`한다 | **O** |
| 4 | `VAR = value`는 VAR에 value를 대입한다 | **X** — `=` 주변 공백 금지. `VAR`라는 명령 실행이 됨 |
| 5 | `$?`는 직전 명령의 종료 코드이고, 성공은 0이다 | **O** |
| 6 | `$!`는 현재 셸의 PID다 | **X** — 직전 백그라운드 명령의 PID (`$$`가 셸 PID) |
| 7 | `VAR="a b"; cmd $VAR`에서 cmd는 인자 2개를 받는다 | **O** — IFS(공백)로 쪼개짐. `"$VAR"`면 1개 |
| 8 | `'$VAR'`는 VAR의 값으로 바뀐다 | **X** — 작은따옴표 안은 치환 안 함 |
| 9 | `file_$argnew.txt`는 arg 값 뒤에 new를 붙인다 | **X** — `argnew` 변수로 해석. `${arg}new` 써야 함 |
| 10 | `export` 안 한 셸 변수도 자식 프로세스의 `getenv()`로 읽을 수 있다 | **X** — 환경에 복사된 것만 |
| 11 | `*.?`는 `stdio.cpp`와 매치된다 | **X** — `?`는 정확히 한 글자 |
| 12 | `>>`는 `O_APPEND`, `>`는 `O_TRUNC`로 연다 | **O** |
| 13 | `cmd > f 2>&1`과 `cmd 2>&1 > f`는 결과가 같다 | **X** — 왼쪽부터 `dup2`. 뒤의 것은 stderr가 터미널로 |
| 14 | `N>&M`은 `dup2(N, M)`이다 | **X** — `dup2(M, N)`: N이 M과 같은 곳을 가리킴 |

## 한 줄 요약

> 셸은 입력을 **단어(문자열)**로 쪼개 첫 단어로 할 일을 정하고, 외부 명령은 **`fork` + `exec` + `wait`**, 셸 상태를 바꾸는 `cd`·`export`는 **내장 명령**으로 처리한다. 변수는 `=` 주변 공백 없이 대입하고, 치환 결과는 **IFS**로 쪼개지므로 `"$VAR"`로 감싼다(`${VAR}`로 이름 경계, `$(cmd)`로 출력 삽입). `export`한 변수만 자식의 **환경**에 복사되고, `*` `?` `[ ]` **글로빙**은 셸이 파일 이름으로 펼친다. `<` `>` `>>` `N>&M`은 `open` + **`dup2`**, `|`는 **`pipe` + `dup2`**이며 리디렉션은 **왼쪽부터** 적용된다.

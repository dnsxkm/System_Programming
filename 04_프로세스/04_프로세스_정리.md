## 1. 프로그램 vs 프로세스

| 구분 | 프로그램 | 프로세스 |
|---|---|---|
| 정체 | 디스크에 저장된 **실행 파일** | 메모리에 올라가 **실행 중인** 프로그램 |
| 상태 | 정적 (그냥 파일) | 동적 (레지스터, 스택, 힙, 열린 파일 등을 가짐) |
| 개수 | 파일 1개 | 같은 프로그램으로 프로세스 여러 개 가능 |
| 식별 | 파일 경로 | **PID** (Process ID) |

## 2. 실행 파일의 섹션과 프로세스 메모리 — `elf.c`

변수를 어디에 어떻게 선언하느냐에 따라 저장되는 위치가 달라진다.

```c
#include <stdio.h>
#include <stdlib.h>

int g1 = 10;                // .data (초기값 있음)
int g2;                     // .bss  (초기값 없음 → 0으로 시작)
const char *s = "hi";       // "hi" 문자열 자체는 .rodata, 포인터 s는 .data

int main(void){             // main의 기계어는 .text
    int local = 5;          // 스택 (섹션 아님)
    int *h = malloc(4);     // h가 가리키는 곳은 힙
}
```

| 섹션 / 영역 | 들어가는 것 | 예시 | 특징 |
|---|---|---|---|
| `.text` | 기계어 코드 | `main` | 읽기 + 실행, 쓰기 불가 |
| `.rodata` | 읽기 전용 상수 | `"hi"` | 수정하면 에러 (segfault) |
| `.data` | **초기값이 있는** 전역/static 변수 | `g1`, `s` | 초기값이 파일에 저장됨 |
| `.bss` | **초기값이 없는** 전역/static 변수 | `g2` | 파일에는 크기만 기록, 실행 시 0으로 채움 |
| 스택 | 지역 변수, 함수 호출 정보 | `local`, `h` 변수 자체 | 함수가 끝나면 사라짐. **섹션이 아님** |
| 힙 | `malloc`으로 받은 메모리 | `h`가 가리키는 4바이트 | `free`할 때까지 유지. **섹션이 아님** |

**주의할 점**

- `const char *s = "hi";` 에서 **문자열 `"hi"`** 와 **포인터 변수 `s`** 는 다른 곳에 있다. `"hi"`는 `.rodata`, `s`는 초기값(`"hi"`의 주소)이 있는 전역 변수라 `.data`.
- `int *h = malloc(4);` 에서도 **포인터 `h`** 는 스택, **`h`가 가리키는 메모리**는 힙.
- 스택과 힙은 실행 파일 안에 없다. 프로세스가 실행될 때 운영체제가 만들어 준다.

### 실제로 확인하기 (macOS)

```bash
gcc -c elf.c -o elf.o
nm -m elf.o          # 심볼이 어느 섹션에 있는지 출력
```

```
0000000000000028 (__DATA,__data) external _g1
0000000000000004 (common) (alignment 2^2) external _g2
0000000000000000 (__TEXT,__text) external _main
                 (undefined) external _malloc
0000000000000030 (__DATA,__data) external _s
```

- `g1`, `s` → `__DATA,__data` (= `.data`) ✅
- `main` → `__TEXT,__text` (= `.text`) ✅
- `g2` → `common`: 초기값 없는 전역 변수는 목적 파일 단계에서 "common 심볼"로 표시되고, **링크 후** bss 영역에 자리 잡는다.
- `malloc` → `undefined`: 라이브러리 함수라 이 파일에는 코드가 없다 (2강의 동적 링킹).

> Linux에서는 `objdump -h elf.o` 또는 `readelf -S elf.o`로 섹션 목록을 볼 수 있다.

## 3. 프로세스 생성 — `fork.c`

```c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    pid_t pid = fork();
    if (pid == 0) {
        puts("In child");
    }   else {
        printf("In parent, child PID = %d\n", pid);
    }
}
```

### `fork()`의 동작

- 호출한 프로세스(부모)를 **그대로 복제**해서 새 프로세스(자식)를 만든다.
- **한 번 호출하면 두 번 반환된다** — 부모에서 한 번, 자식에서 한 번.
- 자식은 부모의 메모리를 복사해서 갖기 때문에, fork 이후 한쪽에서 변수를 바꿔도 다른 쪽에는 영향이 없다.

| 반환값 | 의미 |
|---|---|
| `0` | 지금 **자식** 프로세스에서 실행 중 |
| 양수 | 지금 **부모** 프로세스에서 실행 중, 값은 **자식의 PID** |
| `-1` | fork 실패 (자식이 만들어지지 않음) |

### 실행 결과

```
$ ./fork
In parent, child PID = 27906
In child
```

- 출력 **순서는 보장되지 않는다.** 부모와 자식 중 누가 먼저 실행될지는 스케줄러가 정한다. 실행할 때마다 순서가 바뀔 수 있다.
- PID 값도 실행할 때마다 다르다.

## 4. 자식 기다리기 — `wait.c`

```c
#include <stdio.h>
#include <unistd.h>
#include <stdlib.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();

    if (pid == 0) {                     // 자식
        puts("In child");
        exit(42);
    } else {                            // 부모
        int status;
        waitpid(pid, &status, 0);       // 자식이 끝날 때까지 대기
        printf("Child exited with status %d\n",
        WEXITSTATUS(status));           // 종료 코드(42) 꺼내기
    }
}
```

### 실행 결과

```
$ ./wait
In child
Child exited with status 42
```

- `waitpid()`는 자식이 **종료될 때까지 반환하지 않으므로** 출력 순서가 **항상 같다** (결정적).
- `fork.c`와의 차이: `fork.c`는 순서가 비결정적, `wait.c`는 결정적.

### `waitpid(pid, &status, options)`

| 인자 | 의미 |
|---|---|
| `pid` | 기다릴 자식의 PID (`-1`이면 아무 자식이나) |
| `&status` | 자식의 종료 정보를 받을 변수 |
| `options` | `0`이면 끝날 때까지 대기, `WNOHANG`이면 기다리지 않고 바로 반환 |

### `status`에서 정보 꺼내기

`status`는 종료 코드만 들어 있는 값이 아니라 여러 정보가 비트로 묶여 있다. 그래서 **매크로로 꺼내야 한다.**

| 매크로 | 의미 |
|---|---|
| `WIFEXITED(status)` | 정상 종료(`exit` / `return`)했으면 참 |
| `WEXITSTATUS(status)` | 종료 코드 (`exit(42)`의 `42`) — `WIFEXITED`가 참일 때만 의미 있음 |
| `WIFSIGNALED(status)` | 시그널로 종료됐으면 참 (예: segfault) |
| `WTERMSIG(status)` | 종료시킨 시그널 번호 |

> `printf("%d", status)`로 그냥 찍으면 `42`가 아니라 `10752`(= `42 << 8`) 같은 값이 나온다. 반드시 `WEXITSTATUS`를 쓴다.

### 좀비와 고아 프로세스

| 용어 | 상황 | 결과 |
|---|---|---|
| **좀비** (zombie) | 자식은 끝났는데 부모가 아직 `wait`하지 않음 | 종료 정보를 보관하려고 프로세스 테이블에 남아 있음 |
| **고아** (orphan) | 부모가 자식보다 먼저 끝남 | `init`(Linux) / `launchd`(macOS, PID 1)가 새 부모가 되어 대신 `wait`해 줌 |

→ 부모는 자식을 만들었으면 `wait`/`waitpid`로 **거둬 줘야** 좀비가 쌓이지 않는다.

## 5. 현재 작업 디렉터리 — `현재_작업_디렉터리.c`

- 모든 프로세스에는 **현재 작업 디렉터리**(current working directory, cwd)가 있다.
- 모든 **상대 경로**는 이 디렉터리를 기준으로 해석된다.
- 시스템 콜 `chdir()`로 **설정**하고, `getcwd()`로 **얻는다**.

```c
char *getwd(char *buf);                  // 사용 금지
char *getcwd(char *buf, size_t size);    // 이것을 사용
```

| 함수 | 버퍼 크기 인자 | 문제 |
|---|---|---|
| `getwd(buf)` | 없음 | 경로가 버퍼보다 길면 **버퍼 오버플로** — `gets()`와 같은 문제 |
| `getcwd(buf, size)` | 있음 | 경로가 `size`보다 길면 넘치지 않고 `NULL`을 반환 |

사용 예:

```c
#include <stdio.h>
#include <unistd.h>

int main(void) {
    char buf[1024];
    if (getcwd(buf, sizeof(buf)) != NULL) {
        printf("cwd = %s\n", buf);
    }
    chdir("/tmp");                        // cwd 변경
    getcwd(buf, sizeof(buf));
    printf("cwd = %s\n", buf);            // /tmp (macOS는 /private/tmp)
}
```

> `chdir()`은 **그 프로세스의** cwd만 바꾼다. 프로그램 안에서 `chdir`해도 프로그램이 끝난 뒤 터미널(셸)의 위치는 그대로다. 셸의 `cd`가 외부 프로그램이 아니라 **셸 내장 명령**인 이유가 이것이다.

## 6. macOS vs Linux 차이

| 항목 | Linux | macOS |
|---|---|---|
| 실행 파일 형식 | ELF | Mach-O |
| 섹션 이름 | `.text`, `.data`, `.bss`, `.rodata` | `__TEXT,__text`, `__DATA,__data`, `__DATA,__bss`, `__TEXT,__cstring` |
| 섹션 확인 명령 | `readelf -S`, `objdump -h` | `otool -l`, `nm -m`, `size -m` |
| PID 1 (고아의 새 부모) | `init` / `systemd` | `launchd` |
| `/tmp` 실제 경로 | `/tmp` | `/private/tmp` (심볼릭 링크) |

`fork`, `waitpid`, `getcwd`, `chdir`는 **POSIX 표준**이라 두 환경에서 똑같이 동작한다.

## 7. 실습 중 겪은 에러 & 해결

| 에러 메시지 | 원인 | 해결 |
|---|---|---|
| `call to undeclared library function 'malloc'` | `elf.c`에 `#include <stdlib.h>` 누락 | `#include <stdlib.h>` 추가. C99부터 선언 없이 함수를 쓰면 에러 |
| `unused variable 'local'` (경고) | 선언만 하고 쓰지 않음 | 섹션 확인용 예제라 무시해도 됨 |

## 8. O/X 복습 문제

| # | 문제 | 정답 |
|---|---|---|
| 1 | `fork()`는 부모와 자식에서 각각 한 번씩, 총 두 번 반환된다 | **O** |
| 2 | 자식 프로세스에서 `fork()`의 반환값은 자식의 PID다 | **X** — 자식에서는 `0`, 부모에서 자식의 PID |
| 3 | `fork.c`의 출력 순서는 항상 부모 → 자식이다 | **X** — 스케줄러가 정하므로 보장되지 않음 |
| 4 | `waitpid()`를 쓰면 부모는 자식이 끝날 때까지 기다린다 | **O** |
| 5 | `exit(42)`의 42는 `status` 변수에 그대로 들어 있다 | **X** — `WEXITSTATUS(status)`로 꺼내야 함 |
| 6 | 초기값이 없는 전역 변수는 `.bss`에 들어가고 0으로 시작한다 | **O** |
| 7 | `const char *s = "hi";`에서 `s`와 `"hi"`는 같은 섹션에 있다 | **X** — `"hi"`는 `.rodata`, `s`는 `.data` |
| 8 | 지역 변수와 `malloc`한 메모리는 실행 파일의 섹션에 들어 있다 | **X** — 스택과 힙은 실행 시 만들어짐 |
| 9 | `getwd()`는 버퍼 크기를 받지 않아 위험하다 | **O** |
| 10 | 프로그램 안에서 `chdir()`하면 실행한 셸의 위치도 바뀐다 | **X** — 그 프로세스의 cwd만 바뀜 |
| 11 | 자식이 끝났는데 부모가 `wait`하지 않으면 좀비 프로세스가 된다 | **O** |

## 한 줄 요약

> 프로세스는 **실행 중인 프로그램**이다. 실행 파일의 **섹션**(`.text` / `.rodata` / `.data` / `.bss`)에 **스택·힙**을 더한 메모리를 갖는다. `fork()`는 자신을 복제해 **두 번 반환**하고(자식 `0`, 부모는 자식 PID), `waitpid()`로 자식을 기다려 **종료 코드를 거둔다**. 모든 프로세스에는 **cwd**가 있으며, 크기를 받지 않는 `getwd()` 대신 `getcwd()`를 쓴다.

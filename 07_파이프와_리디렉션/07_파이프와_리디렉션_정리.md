## 1. 프로세스 간 통신 (IPC)

IPC(Interprocess Communication)는 프로세스들이 **협력**하는 방법이다. POSIX의 IPC 종류:

- **파이프** ← 이번 강의
- 소켓
- 공유 메모리
- 시그널
- 프로세스 종료 값 (4강 `exit(42)` → `WEXITSTATUS`)
- 환경 변수 (8강)

### UNIX 파이프 (1972년부터)

- 한쪽 끝에 쓴 데이터를 다른 쪽 끝에서 읽는 **파일 같은 추상화**.
- 읽고 쓰기는 **Unix I/O 함수**(`read`/`write`) 그대로.
- 파이프는 **파일 디스크립터**로 표현된다.

UNIX 유틸리티 대부분은 **fd 0에서 읽고 fd 1에 쓴다**. 그래서 표준 입출력에 파이프를 연결하면 **한 프로세스의 출력이 다른 프로세스의 입력**이 된다 (`ls | wc -l`).

## 2. 파이프 만들기 — `pipe_simple.c`

```c
int pipefd[2];
if (pipe(pipefd) < 0) {
    perror("pipe");
}
```

| | 역할 | 기억법 |
|---|---|---|
| `pipefd[0]` | **읽기** 전용 끝 | stdin(0)과 같은 순서 |
| `pipefd[1]` | **쓰기** 전용 끝 | stdout(1)과 같은 순서 |

```c
int pipefd[2], rval, wval = 42;
pipe(pipefd);
write(pipefd[1], &wval, sizeof(wval));
read(pipefd[0], &rval, sizeof(rval));
printf("%d\n", rval);
```

```
$ ./pipe_simple
pipefd[0] = 3 (read), pipefd[1] = 4 (write)
42
```

- 0, 1, 2는 이미 쓰고 있으니 비어 있는 가장 작은 번호 3, 4를 받는다.
- 파이프는 **커널 안의 버퍼**이고, 프로세스는 fd를 통해서만 접근한다.

## 3. fork와 파이프 — `pipe_fork.c`

`fork()`는 fd 테이블을 복제하므로, **fork 전에 만든 파이프는 부모와 자식이 함께 쓸 수 있다.**

```c
pipe(pipefd);
if ((pid = fork()) == 0) {          // 자식: 쓰기만 함
    close(pipefd[0]);               // 안 쓰는 읽기 끝을 닫음
    write(pipefd[1], "Hello", 6);
} else {                            // 부모: 읽기만 함
    close(pipefd[1]);               // 안 쓰는 쓰기 끝을 닫음
    read(pipefd[0], buf, 6);        // 자식이 쓸 때까지 block
    puts(buf);
}
```

```
$ ./pipe_fork
Hello
```

### 커널 버퍼에서 일어나는 일 (슬라이드 13~16)

| 단계 | 커널 버퍼 | 상태 |
|---|---|---|
| ① | `[ ][ ][ ][ ][ ][ ]` | 자식은 쓰기 시작, **부모는 read에서 block** (버퍼가 비어 있음) |
| ② | `[H][e][l][l][o][\0]` | 자식이 "Hello" 6바이트를 씀 |
| ③ | `[H][e][l][l][o][\0]` → 부모가 꺼냄 | 부모의 read가 이어서 진행 |
| ④ | `[ ][ ][ ][ ][ ][ ]` | 부모가 `puts(buf)` |

**Safe Pipe and Fork**: 자식은 **읽기 끝**을, 부모는 **쓰기 끝**을 닫는다. 쓰지 않는 끝을 닫아야 다음 절의 EOF 문제가 생기지 않는다.

## 4. EOF는 언제 오나 — `pipe_eof.c`

- 파이프의 읽기 끝은 **쓰기 끝이 모두 닫혔을 때** EOF(0)를 반환한다.
- 쓰기 끝 fd가 **하나라도 열려 있으면** 읽기 끝은 **절대 EOF를 반환하지 않는다.**
- 파이프 fd는 `fork`할 때 **복제**된다. 열린 파일 항목은 가리키는 fd가 하나라도 있으면 열려 있다.

```c
pipe(pipefd);
if (fork() == 0) {
    close(pipefd[0]);
    write(pipefd[1], "data", 4);
    close(pipefd[1]);               // 자식은 쓰기 끝을 닫고 종료
    return 0;
}
if (close_write)
    close(pipefd[1]);               // 부모도 쓰기 끝을 닫을까?
while ((n = read(pipefd[0], buf, sizeof(buf))) > 0)
    printf("read %d bytes\n", n);
printf("read returned %d -> EOF\n", n);
```

```
$ ./pipe_eof close              # 부모도 쓰기 끝을 닫음
read 4 bytes
read returned 0 -> EOF

$ timeout 2 ./pipe_eof          # 부모가 쓰기 끝을 열어 둠
read 4 bytes
                                # 여기서 영원히 멈춤 → 2초 뒤 timeout이 종료
```

자식은 쓰기 끝을 닫았지만 **부모 자신이 쓰기 끝을 들고 있어서** 커널은 "아직 누군가 쓸 수 있다"고 보고 read를 계속 기다리게 한다. → **안 쓰는 끝은 반드시 닫는다.**

## 5. 버퍼 크기와 교착 상태 — `pipe_capacity.c`

- 버퍼가 **가득 차면 write가 block**된다.
- 버퍼가 **비어 있으면 read가 block**된다.

그래서 **한 프로세스 안에서** 파이프를 쓰면 교착 상태(deadlock)가 생기기 쉽다: 버퍼 크기보다 많이 write → block → 버퍼를 비워 줄 read가 없음 → 영원히 멈춤. 부모 하나가 자식 여러 개와 명령·응답 파이프를 주고받는 구조(슬라이드 17)에서 교착이 생기면 성능이 크게 떨어진다.

### 해결: non-blocking

원인은 read/write가 **block**되는 것이므로, **non-blocking**으로 바꾸면 막을 수 있다.

```c
#include <fcntl.h>
fcntl(pipefd[0], F_SETFL, O_NONBLOCK);
fcntl(pipefd[1], F_SETFL, O_NONBLOCK);
```

```
$ ./pipe_capacity
read on empty pipe : errno = 11 (Resource temporarily unavailable)
write on full pipe : errno = 11 (Resource temporarily unavailable)
pipe capacity      : 65536 bytes
```

- 빈 파이프 read, 꽉 찬 파이프 write 모두 기다리지 않고 **-1 + `EAGAIN`(errno 11)**을 반환한다.
- 1바이트씩 non-blocking으로 써 보면 리눅스 파이프 버퍼는 **65,536바이트(64KB)**다.

## 6. 커널의 3단 테이블 — `02_fd_공유/`

fd는 **작은 정수**이고, 그 프로세스의 **열린 파일 테이블의 인덱스**다. 실제로는 테이블이 3단계다.

```
 디스크립터 테이블          열린 파일 테이블             v-node 테이블
 (프로세스마다 하나)        (모든 프로세스가 공유)       (모든 프로세스가 공유)
┌──────┐
│ fd 0 │──────────────→ ┌─────────────┐          ┌─────────────┐
│ fd 1 │──────────────→ │ 파일 위치    │────────→ │ 파일 종류    │  File A
│ fd 2 │                │ refcnt = 1  │          │ 파일 크기    │  (터미널)
│ fd 3 │                └─────────────┘          │ 접근 권한    │
│ fd 4 │──────────────→ ┌─────────────┐          └─────────────┘
└──────┘                │ 파일 위치    │────────→ ┌─────────────┐
                        │ refcnt = 1  │          │ ...         │  File B
                        └─────────────┘          └─────────────┘  (디스크)
```

| 테이블 | 누구 것 | 담는 것 |
|---|---|---|
| 디스크립터 테이블 | **프로세스마다** | fd 번호 → 열린 파일 항목 포인터 |
| 열린 파일 테이블 | **전체 공유** | **현재 파일 위치**, 참조 수(refcnt), 열린 모드(읽기/쓰기) |
| v-node 테이블 | **전체 공유** | 파일 종류, 크기, 권한, 디스크 위치 (`stat` 구조체의 정보) |

열린 파일 테이블에 메타데이터를 캐시해 두기 때문에 read/write할 때마다 권한 검사나 디스크 인덱싱을 다시 하지 않는다.

### 세 가지 공유 상황 실험 (`abc.txt` = "abc")

```
$ ./open_twice                       # 같은 파일을 open 두 번
fd1=3 -> 'a', fd2=4 -> 'a'

$ ./fork_share                       # open 후 fork
child  read 'a'
parent read 'b'

$ ./dup_share                        # open 후 dup
fd1=3 -> 'a', fd2=4 -> 'b'
```

| 상황 | 열린 파일 항목 | 파일 위치 | 결과 |
|---|---|---|---|
| `open` 두 번 | **2개** (각각 refcnt=1) | **따로** | 둘 다 'a' |
| `fork` | **1개를 공유** (refcnt=2) | **공유** | 자식이 'a'를 읽어 위치가 1로 → 부모는 'b' |
| `dup` | **1개를 공유** (refcnt=2) | **공유** | fd1이 'a', fd2는 이어서 'b' |

- `fork`는 디스크립터 테이블을 **복사**한다. 복사된 fd는 같은 열린 파일 항목을 가리키므로, **파일 위치 변경**이나 다른 열린 파일 속성 변경이 **양쪽에 영향**을 준다.
- `exec`를 해도 이 상황은 그대로다 (`O_CLOEXEC`/`fcntl`로 바꿀 수 있음). 그래서 셸이 연 fd를 `exec`된 프로그램이 이어받는다.

## 7. dup / dup2와 리디렉션 — `redirect.c`

```c
#include <unistd.h>
int dup(int fd);                    // fd를 복사, 비어 있는 가장 작은 번호를 반환
int dup2(int oldfd, int newfd);     // oldfd를 newfd 번호로 복사 (newfd가 열려 있으면 먼저 닫음)
```

fd를 복사하면 **두 fd가 같은 열린 파일 항목**을 가리킨다. 원하는 파일을 **원하는 fd 번호(0, 1, 2)에 놓는 것**이 리디렉션이다.

```c
fd = open("output.txt", O_WRONLY | O_CREAT | O_TRUNC, 0666);
dup2(fd, 1);                        // fd 1(stdout)이 output.txt를 가리키게 함
close(fd);                          // 원래 fd는 더 필요 없음
puts("Redirected output!");         // 화면이 아니라 파일로 감
```

```
$ ./redirect
$ cat output.txt
Redirected output!
```

### 테이블로 보면 (슬라이드 33~34)

| 단계 | fd 1 | fd 4 | File A (터미널) refcnt | File B (output.txt) refcnt |
|---|---|---|:---:|:---:|
| `open` 후 | File A | File B | 1 | 1 |
| `dup2(4, 1)` 후 | **File B** | File B | **0** (닫힘) | **2** |
| `close(4)` 후 | File B | - | 0 | 1 |

`puts`는 fd 1에 쓴다는 것만 알 뿐, fd 1이 무엇을 가리키는지는 모른다. 셸은 **자식 프로세스에서 `exec` 직전에** 이 작업을 해서 `> output.txt`를 구현한다.

## 8. 셸 파이프라인 직접 만들기 — `pipeline.c`

슬라이드 35~36의 질문: "`cat input.txt | wc -l`을 어떻게 구현할까?" 같은 구조로 `ls -1 /usr | wc -l`을 만들었다.

```c
pipe(pipefd);

if ((pid1 = fork()) == 0) {         // 왼쪽 명령: stdout → 파이프 쓰기 끝
    dup2(pipefd[1], 1);
    close(pipefd[0]);
    close(pipefd[1]);
    execlp("ls", "ls", "-1", "/usr", NULL);
}

if ((pid2 = fork()) == 0) {         // 오른쪽 명령: stdin ← 파이프 읽기 끝
    dup2(pipefd[0], 0);
    close(pipefd[0]);
    close(pipefd[1]);
    execlp("wc", "wc", "-l", NULL);
}

close(pipefd[0]);                   // 부모는 파이프를 안 씀 → 양쪽 다 닫기
close(pipefd[1]);
waitpid(pid1, NULL, 0);
waitpid(pid2, NULL, 0);
```

```
$ ./pipeline
10
$ ls -1 /usr | wc -l
10
```

셸이 `cmd1 | cmd2`를 실행하는 순서 (8강 슬라이드 29):

1. `pipe()`로 파이프 생성
2. `fork()` 두 번 (cmd1용, cmd2용)
3. `dup2()`로 연결: `pipefd[1]` → cmd1의 fd 1, `pipefd[0]` → cmd2의 fd 0
4. 각 자식에서 `exec()`
5. cmd2가 끝날 때까지 `wait`

> **부모가 `pipefd[1]`을 닫지 않으면** `wc`는 EOF를 받지 못해 끝나지 않고, 부모는 `waitpid(pid2)`에서 영원히 기다린다 (4절과 같은 원리).

## 9. 실습 중 겪은 에러 & 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| `pipe_eof`가 끝나지 않음 | 부모가 쓰기 끝을 열어 둠 → EOF가 오지 않음 | 안 쓰는 끝은 `close`. 실험이라 `timeout 2`로 강제 종료 |

## 10. O/X 복습 문제

| # | 문제 | 정답 |
|---|---|---|
| 1 | `pipe(pipefd)`에서 `pipefd[0]`이 쓰기 끝이다 | **X** — `[0]`이 읽기, `[1]`이 쓰기 (stdin/stdout 순서) |
| 2 | 파이프는 커널 버퍼이고 fd로 접근한다 | **O** |
| 3 | 빈 파이프에서 read하면 0(EOF)을 반환한다 | **X** — 쓰기 끝이 열려 있으면 block. 모두 닫혀야 EOF |
| 4 | 자식이 쓰기 끝을 닫으면, 부모가 쓰기 끝을 열어 둬도 부모의 read는 EOF를 받는다 | **X** — 쓰기 끝 fd가 하나라도 열려 있으면 EOF 없음 |
| 5 | 리눅스 파이프 버퍼는 실습에서 64KB였다 | **O** — 65,536바이트 |
| 6 | `O_NONBLOCK` 파이프에서 꽉 찬 상태로 write하면 `EAGAIN`이 난다 | **O** |
| 7 | 디스크립터 테이블은 모든 프로세스가 공유한다 | **X** — 프로세스마다 하나. 열린 파일·v-node 테이블이 공유 |
| 8 | 파일 위치(file position)는 열린 파일 테이블에 저장된다 | **O** |
| 9 | 같은 파일을 두 번 `open`하면 두 fd의 파일 위치는 공유된다 | **X** — 열린 파일 항목이 2개라 따로 |
| 10 | `fork` 후 자식이 파일을 읽으면 부모의 파일 위치도 바뀐다 | **O** — 같은 열린 파일 항목을 공유 |
| 11 | `dup2(fd, 1)`은 fd 1을 fd와 같은 파일을 가리키게 만든다 | **O** |
| 12 | `cmd1 \| cmd2`에서 cmd2의 stdin은 `pipefd[1]`에 연결된다 | **X** — cmd2의 fd 0 ← `pipefd[0]`, cmd1의 fd 1 → `pipefd[1]` |

## 한 줄 요약

> **파이프**는 파일처럼 읽고 쓰는 **커널 버퍼**(리눅스 64KB)로, `pipe()`가 **[0] 읽기 / [1] 쓰기** fd를 준다. 버퍼가 비면 read가, 차면 write가 block되고(`O_NONBLOCK`이면 `EAGAIN`), **쓰기 끝이 모두 닫혀야** EOF가 온다. fd는 **프로세스별 디스크립터 테이블 → 공유 열린 파일 테이블(파일 위치, refcnt) → v-node 테이블**을 거치는 간접 포인터라, `fork`와 `dup`은 **파일 위치를 공유**한다. `dup2(fd, 1)`로 원하는 파일을 표준 fd에 놓는 것이 **리디렉션**이고, `pipe` + `fork` + `dup2` + `exec`가 셸의 `|`다.
